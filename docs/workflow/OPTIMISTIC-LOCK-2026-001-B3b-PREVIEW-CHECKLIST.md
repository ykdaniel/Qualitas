# OPTIMISTIC-LOCK-2026-001 B3b 預覽檢查表

- **環境**：隔離環境（網址、帳號由開預覽的工作階段提供，密碼不寫在文件裡）。
- **做法**：兩個分頁 A、B，同一個帳號。

## 1. IAM 帳號＋範圍共用版本（同一個視窗連續存兩次，不會自己撞 409）
1. A 在 IAM 打開預覽用的帳號，在「資料範圍」區塊改專案後按範圍的「儲存」→ 成功，視窗不關。
2. 接著在同一個視窗改「Company」，填稽核原因，按帳號的「儲存」→ **成功**（用的是範圍存檔回傳的版本）。
3. 反過來再試一次：先存帳號（若範圍有未存的修改，會詢問），再存範圍 → 都成功。
4. 409：B 先打開同一個帳號；A 存檔之後，B 存帳號或存範圍 → 409 →「重新載入這筆」→ 確認 → 視窗重新打開，顯示 A 的內容。
5. 關掉視窗再打開同一個帳號 → 存檔成功（清單裡的版本已經是最新的，**以前範圍存完不會寫回，重開會撞 409**）。
6. 新建帳號並綁承包商：按「新增帳號」，選專案和承包商後新增 → 成功（系統先建立帳號，再用建立回傳的版本寫入承包商綁定）；打開這個新帳號再存一次 → 成功。
7. 存檔中：按帳號的「儲存」後立刻按「取消」或範圍的「儲存」→ 沒有反應或是停用（存檔中不能關閉，也不會同時送出兩次）。
（注意：任一區塊 409 後的「重新載入這筆」會整個視窗重開，另一區塊還沒存的修改也會捨棄。）

## 2. 承包商人員：列上直接編輯
1. A、B 都打開同一家承包商，在人員清單上按同一個人的「編輯」。
2. A 改職稱後按 ✓ → 成功。
3. B 改電話後按 ✓ → 409 →「重新載入這筆」→ 確認 → 這一列重新進入編輯，顯示 A 改的職稱。
4. 啟用／停用：A 停用某人後，B（清單還沒更新）按同一個人的停用 → 409 →「重新載入這筆」→ **不需確認**，清單直接更新。

## 3. KM 主檔
1. A、B 都打開預覽用的 KM 文章編輯視窗。
2. A 改標題後儲存。
3. B 改內容後儲存 → 409 →「重新載入這筆」→ 確認 → 視窗重新讀取，顯示 A 的標題（KM 視窗之後會由 KM-DOCS D2 取代）。

## 4. 補看
- 承包商、專案、角色各試一次「兩個分頁同筆存檔」→ 409 → 重新載入後顯示對方的內容。
