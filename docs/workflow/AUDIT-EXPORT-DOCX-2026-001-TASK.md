## 範圍
1. 後端：新增 `GET /api/audit/{audit_id}/export-docx`，回傳 `.docx`。
   - 權限 `audit:view`（RoleChecker(AUDIT_VIEW)），資料範圍沿用 `get_audit(scope)`：不存在或不在範圍內一律 404「Audit not found」。
   - 用共用的 `core/docx_builder.py` 組出 NCR 報告版面（抬頭、灰底章節列、標籤／值表格、文字框、簽核格），中英雙語。
   - 內容是已儲存的紀錄：
     1. 稽核資訊（編號、狀態、標題、專案、受稽核廠商、起訖日期、地點）
     2. 稽核團隊（專案經理、工作包／技術負責人、主任稽核員、協同稽核員）
     3. 稽核範圍與準則（準則、選用模板、範圍描述）
     4. 查檢結果（統計：總數／完成率／符合／不符合／注意，算法同精靈；明細表：條文編號、條文與查檢重點、結果、備註、更新日期）
     5. 稽核發現與總結
     6. 簽核（主任稽核員、受稽核方代表、專案經理）
   - 舊資料或異常資料（JSON 欄位壞掉、不是 list、項目不是物件；只有 project_name 沒有 project_id；含 XML 不允許的控制字元）不能讓匯出失敗。
2. 前端：精靈第 4 步「列印報告」旁加「匯出 Word」按鈕。
   - 只有已儲存的紀錄才顯示（新紀錄第一次儲存草稿後出現）。
   - 有未儲存的修改時不匯出，提示先按「儲存草稿」（匯出內容取自伺服器上已儲存的資料）。
   - 唯讀（只能檢視的使用者、Closed／Void）照樣可以匯出。列印時不顯示。
   - `useDraftGuard` 多回傳 `dirty`（只新增欄位，其他呼叫端不受影響）。
3. 測試：後端 HTTP 測試（內容、異常資料、權限與範圍）、隔離環境瀏覽器檢查腳本與種子資料。
