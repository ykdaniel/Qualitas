## 發現（最多三項，依影響填表效率排序）

### Finding 1 — Inspection Plan 項目面板的內容欄位全部是單行輸入框，長文字會被截斷
分類：**介面問題，可直接改善**。
Activity／Standard／Criteria／Check Time／Method 等欄位在新增/編輯/複製共用
的面板裡都是固定高度單行 `<input>`，真實長度的工程規範文字（80-140 字元）
一律被截斷只看得到開頭片段，必須點進欄位捲動才能看到完整內容；對照列表本身
的呈現完全沒有這個問題（自然換行、不截斷）。改善方案：這幾組欄位改用
`<textarea>`（或自動依內容調整高度），不涉及資料結構異動。詳見 handoff
文件 Finding 1，截圖：`finding1-copy-panel-truncated-fields.png`。

### Finding 2 — i18n key `itp.submissionDate` 的顯示文字是「Updated Date」，與 key 名稱不一致
分類：**觀察到的現況，語意與修正範圍待確認**（審查已更正：不是單純翻譯錯字，
下修為此分類，不再稱「可直接改善」）。
`LanguageContext.tsx:1126,2513` 這個 key 的顯示文字在英文/中文都是「Updated
Date」/「更新日期」，與 key 名稱 `submissionDate` 字面不一致——這只證明**命名
與顯示文字不一致**，**不能單憑程式變數命名推論這個欄位的業務意義一定是「送審
日期」**，實際語意需要使用者/業主確認。另外，**審查已指出並經覆核確認**：這個
key **不是只用在表單這一處**——`react-app/src/components/ITP/columns.tsx:133`
的清單欄位標題（`DataTableColumnHeader` 的 `title`）也呼叫同一個
`t('itp.submissionDate')`；而列印輸出（`ITPPrintTemplate.tsx:33`）用的是
**另一組獨立、未走 i18n key 的硬編碼文字「Date:」**。也就是說同一個欄位在
表單、清單欄位標題、列印輸出三處，目前分別顯示「Updated Date」／「Updated
Date」（清單與表單共用同一個 key）／「Date」，是三種不同的呈現，不是只有表單
一處的孤立文字問題。**撤回**先前「只影響這一個欄位、可直接修正翻譯」的判斷；
若要改，需要先確認（a）這個欄位的真正業務語意、（b）改了 key 文字後清單欄位
標題會同步變動是否符合預期、（c）列印的「Date:」要不要一併對齊。詳見 handoff
文件 Finding 2（已依此更正），截圖：`finding2-submissiondate-mislabeled.png`
（截圖本身仍如實呈現「表單欄位顯示 Updated Date」這個現況觀察，未被撤回的是
這張截圖與其直接呈現的文字事實，撤回的是對這個事實的過度推論與修正範圍）。

### Finding 3 — Subject（主旨）欄位沒有必填驗證，可以存出完全空白主旨的 ITP
分類：**需確認的業務規則**。
General Information 只有 Contractor 標示必填並有驗證；Subject 沒有星號也沒有
驗證，實測可以留白直接存檔成功，清單出現一筆主旨完全空白的紀錄——這是**本輪

證明 ITP 也應該必填，這是兩個獨立模組，是否要對齊是業務決策，不是靠「別的
模組有做」就能類推的結論。**本輪只記錄現狀，分類維持待決策，不預設答案**。
