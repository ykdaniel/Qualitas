## 規則（所有工作階段）
1. **部署一次一批。** 要在 NAS 放檔案（`~/deploy-*` 暫存）或請使用者重建之前，先通知協調中心，排進「部署佇列」並取得「可以開始」後才動。一次後端重建只含一批。
2. **部署前核對正式站。** 以「目前正式站版本」為基準重做雜湊預檢；不以舊預檢或他人的暫存為前提。
3. **只提交自己的修改。** 共用檔（見下表）只暫存自己的區塊；不提交、不推送他人未提交的修改。
4. **改到他人正在改的檔案前先講。** 對方有未提交修改時，先用 SendMessage 協調（等對方提交，或約定只改哪幾行）。
5. **推送與合併 main 由協調中心統一處理：** 各工作階段只做本地 commit，把 hash 傳給協調中心； 經 PR、CI 綠燈，以 `--match-head-commit` 鎖定驗證過的版本合併；`main`＝正式站。
6. **GPT 審查暫停**（使用者 2026-10-11：「GPT 沒有額度了，目前不給他審查」）：各輪不要送 GPT、不要產生「給 GPT」訊息當作待辦。需要審查時改用工作階段自己的獨立審查代理（Claude），並在 REVIEW 註明審查者；或由使用者決定略過審查。等額度恢復再補審。
7. 不碰：使用者預覽 8240／3240、8198／3198；開發資料庫 `backend/qualitas.db`；根目錄部署控制文件（除非該任務明確要求）。
